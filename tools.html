tools

Hosts, tool lists and sub-agents: what Ramabana adds on top of the shalya toolset.

A model can only write text. To read a file or run a command, it calls a tool. A tool is a Python function. The backend turns its name, docstring and typed parameters into a schema that the model sees. Ramabana’s tools come from shalya.

The tools act through a host. A host is the object that decides which folders are open (its roots), whether files may be written and which other services exist. Such services include a shell, a Python kernel, git and the web. Each service is a capability group. A host declares a group by inheriting the class that names it, such as CodeHost or WebHost. Host.provides lists the groups a host declares. Every host has the file group. The tools that need one capability group form a tool group. The shell group, for example, is run_shell, run_shell_bg, shell_output and shell_stop.

Shalya holds the host classes, the functions that build each tool group, the conventions tool results follow (err writes a failure that failed recognises), and the skills registry. This module re-exports all of them. Code that imports them from ramabana.tools keeps working. The alias sys.modules[__name__] = ramabana.tools, which Leela (the notebook editor) uses, keeps resolving. New code imports them from shalya.

What this module adds depends on parts of the agent that shalya does not know. A sub-agent needs a Backend to talk to and a Run to record it. draws_itself needs a ModelSpec. The sections below cover a host that refuses everything, the image tools, tools_for, which builds the tool list a turn gets, delegation to sub-agents, and attachments.

A host with nothing behind it

NullHost is a host with no folders and no services. Checking a path raises HostError, reading returns nothing, and writing or deleting raises. It declares no capability group beyond file. Its writes is False, and tools_for gives it view_file and nothing else. Use it in a test, or wherever code needs a host object that must not touch the disk. Drawing

Shalya’s generate_image tool makes pictures. Some models can draw themselves when they are given the image tool. For any other model the prompt goes to a separate image model. Which case applies is a fact about the turn’s model, so shalya asks for it as a callable, and this module supplies the callable.

draws_itself looks up a model’s capabilities with spec_caps and returns True when image is among the tools the model supports (Caps.tools). The supported_output_modalities field cannot answer this: it says no for every chat model, because it describes what a model returns without being asked.

Assembling the tool list

tools_for decides which tools a host gets. It asks Host.provides for the capability groups and adds the tool group for each. A get_skills callable adds read_skill, and extra adds extension tools. drop removes groups by name, such as 'shell' or 'image'. optin adds groups that are off by default: exhash (the hash-addressed edit_file), research, author, legacy (tool names from older releases) and browser.

Shalya has a tools_for of its own. Use this one in Ramabana code, because it also builds the image group from the turn’s model through get_spec and on_media, which a host cannot know. The image group comes only when an image key is set and the host can write, since generate_image saves files. On a LocalHost without litesearch installed, search_code is left out.

small_tool marks an extension tool to keep in the small profile, the short catalog a local model or a small context window gets. ToolCatalog wraps a tool list once and answers questions about it: each tool’s group, which tools write, which have effects, and a read-only copy. ToolEntry is one row of it.

Sub-agents

A sub-agent is a separate conversation with a model, started to answer one question for the agent that asked. Handing a question over this way is delegation. Delegation saves context. It does not save time. A broad question can take twenty tool calls to answer. If the main agent made them itself, every result would stay in its conversation. Delegated, the same work costs the main conversation one question and one answer. The sub-agent’s conversation is thrown away when it finishes.

A sub-agent gets read-only tools unless the session allows it to write. NO_SUB lists the tools it never gets by default: the five delegation tools and the two watch tools (watch and cancel_watch). A watch would outlive the sub-agent’s task. A session that allows nesting passes its own block. The sub-agent may then delegate in turn. These constants set the limits:

Constant Value Meaning
SUB_MAX_STEPS 80 Steps a delegation gets when it names none.
SUB_STEP_CEILING 400 Most steps a delegation may ask for under auto, and the most a numeric session cap may be.
SUB_MIN_STEPS 20 Fewest steps a delegation runs with when it asks for fewer.
SUB_TIMEOUT 1800 Seconds before a delegation is stopped. 0 never stops it.
SUB_STEP_SECONDS 20 Under auto steps, a delegation with the default time limit gets its steps times this many seconds, when that is more than SUB_TIMEOUT.
SUB_TIMEOUT_CEILING 10800 Most seconds that step-based limit can reach.
SUB_UNFINISHED 300 A reply with no tool call and no state: line, shorter than this many characters, counts as a progress line and not a report.
SUB_SLOTS 4 Sub-agents working at once across one agent’s whole delegation tree.

A briefing is the standing instructions a model gets before the conversation starts, its system prompt. sub_briefing builds a sub-agent’s briefing from parts in this order: SUB_SP_HEAD, which every sub-agent gets, then SUB_READ_SP or SUB_WRITE_SP, then an optional note on how much of the answer the caller will read, then notes for the model’s family.

read_only, from shalya, filters a tool list down to what an agent may have when it must not change anything. Write tools are dropped, or swapped for a safe version where the tool has one. block drops tools by name, and Ramabana passes NO_SUB. effects=False also drops the acting tools, those that do something without writing a file, such as inspect_python, shell_stop and generate_image. Shalya marks them with acts and lists them in ACTING_TOOLS. Use effects=False for a surface that may look and propose but never act.

A safe version can fix an argument. In the second cell below, read_url still fetches the page, but its remember parameter is gone and it no longer stores the page in the vault.

max_calls puts a hard budget on the list. Past it, every tool returns a message telling the model to stop and answer. Local engines run their own tool loop. Ramabana cannot stop them between steps. A budget inside the tools is the one limit that works on every backend. Below, the second search is refused.

budgeted = read_only(ts, max_calls=1, block=NO_SUB)
search = next(t for t in budgeted if t.__name__ == 'search_code')
search('return'), search('return')

delegate asks one question of a sub-agent. It spawns a new conversation on the same engine as backend, hands it the tools that read_only lets through (with writes=True, the write tools too), sends the question, and closes the conversation in a finally block whether or not it succeeded. The tools carry a call budget of four times max_steps. A short reply with no tool call and no state: line gets one nudge (SUB_NUDGE), and the sub-agent answers again. delegate returns the answer text. An empty or repetitive answer is replaced by a notice that the delegation failed. A sub-agent that raised gives an error result. timeout cancels the run after that many seconds, and slots, a shared Slots, makes it wait for a free place among the sub-agents working at once. A sub-agent waiting on sub-agents of its own lends its place back. A full tree of delegations then cannot deadlock.

Use delegate for one question. delegate_many, below, asks several, and subagent_tools wraps both as tools a model can call.

delegate_many asks several questions at once, one sub-agent each, and returns the answers in the order the questions were asked. It registers every child run with the parent before any starts. Cancelling the parent then reaches all of them. The last example on this page shows that. Questions to cloud models run in parallel, up to n_workers (default 4) at once. Questions run one at a time when sub-agents may write, and questions to local models run one at a time. An engine such as LiteRT holds one conversation at a time, and parallel runs would race for it.

delegate_many(be, ['what imports fastllm?', 'where is compaction triggered?'], tools=ts)

The delegation tools take a callable that returns a backend. Each call asks for the current session’s backend. After a /model switch the next sub-agent runs on the new model.

delegate_async starts a sub-agent in the background and returns at once. The turn can carry on while the sub-agent works. Background keeps track of those runs. start registers a run before its thread begins. A status call therefore always finds the id that start returned. At most mx runs reach a model at once (ASYNC_MAX, 4 by default) and the rest wait as pending. status, result and cancel answer for one run, and status with no id answers for all. The last keep answers are held. close, called when the session ends, cancels every run and refuses new work.

The examples hold two runs behind a Background with one place, cancel a run still waiting, close a Background, catch a run that raised, and show an answer dropped once newer ones push it out.

model and effort name a model and an effort level for every question, or give a list with one per question. Attachments

A prompt can carry files: pictures and sound. These helpers live here and not in the terminal module. A host that only sends files then does not load the terminal UI. media_paths reads a paste or a dropped file in the shapes terminals deliver it, quoted, backslash-escaped or as a file:// URL, and returns the media files it names, or an empty list for any other text. attach_refs finds @path references in a prompt. clipboard_png reads a picture from the clipboard with pngpaste, wl-paste or xclip, whichever is installed. Attachment holds one file’s bytes, read once. media_parts and media_note turn a list of attachments into what the message sends: the bytes the model accepts, and a note listing every file. Audio goes to the model only when it accepts audio; otherwise the note gives the file’s path.
