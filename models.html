models

The model catalog: the models a picker offers for each provider, and what each provider’s own listing adds.

The catalog

CATALOG maps each provider to the model ids a picker offers without any network request, in display order.

  • claude is what Claude Code’s --model accepts: the tier names fable, opus, sonnet and haiku, which follow the newest model of each family, then the full ids.
  • anthropic is the same models through the Anthropic API.
  • openai and gemini are the models offered through those APIs.
  • codex is what Codex’s own picker lists.

claude_ids returns the full Claude ids without the tier names. claude_aliases maps each tier name to the last id of that family in CATALOG. A newer Opus added at the end of the family’s ids becomes the id that opus means.

Live discovery

LIVE holds one function for each provider that can be asked for its models. The function returns the ids the provider lists. It returns [] when it cannot ask: no key, no file, no network, or an answer it cannot read. It never raises.

  • openai_ids asks OpenAI’s /v1/models with $OPENAI_API_KEY.
  • anthropic_ids asks Anthropic’s /v1/models with $ANTHROPIC_API_KEY. It serves both anthropic and claude. Claude Code runs the same models.
  • codex_ids asks no server. It reads models_cache.json under $CODEX_HOME, which defaults to ~/.codex, where Codex keeps its picker list. It returns the entries marked visibility: 'list'. The test below writes a small cache file and reads it back.

What a live listing may add

A provider’s listing holds everything it serves: dated snapshots, fine-tunes, realtime and audio models, embeddings, moderation, image and search models. A picker wants none of these. _current decides which listed ids a picker may show. It hides an id by the kind of model, not by generation. A new generation appears the day the provider lists it. _current hides ids that end in an ISO date, such as gpt-6-astra-2026-09-01. It keeps ids that end in an eight-digit date, such as claude-haiku-4-5-20251001. provider_models drops those from a live listing. It keeps one only when CATALOG already names it. Older chat generations (gpt-4*, gpt-3.5*, claude-2-* and claude-3-*) appear only with legacy=True. The cell below lists ids that _current keeps, ids it always hides, and ids it shows only with legacy.

for ok in ('gpt-6-astra', 'gpt-7', 'o5-mini', 'claude-fable-5-1', 'claude-haiku-4-5-20251001', 'gemini-3.5-flash'): assert _current('openai', ok), ok
for hidden in ('gpt-6-astra-2026-09-01', 'gpt-3.5-turbo-0125', 'ft:gpt-3.5-turbo-0125:org::abc', 'ada:ft-org-2023-04-06-20-44-19', 'gpt-realtime', 'gpt-6-audio', 'gpt-image-2', 'gpt-6-transcribe', 'tts-1', 'gpt-live-1', 'gpt-3.5-turbo-instruct', 'text-embedding-4', 'omni-moderation-latest', 'dall-e-3', 'whisper-1', 'davinci-002', 'babbage-002', 'sora-2', 'computer-use-preview', 'gpt-5-search-api', 'gpt-4o-search-preview', 'o3-deep-research', 'chat-latest', ''):

What a picker offers

provider_models(p) returns the list a picker shows for provider p. It starts with the CATALOG ids in their order. It then adds the ids from the live listing that _current admits and that do not end in an eight-digit date, newest first by version number. No id repeats. ramabana.core.probed remembers the live answer for five minutes. If the listing fails, the result is the catalog alone. A provider that is in neither CATALOG nor LIVE returns [].

The first cell below fakes an OpenAI listing. The second makes every listing fail. The third fakes Anthropic’s endpoint and shows that claude and anthropic share one request.

def provider_models(

Ids a picker offers for provider p: the curated ones in their order, then what live discovery adds. The live list is kept on disk, so a new process shows the last one at once and asks again in the background.

from ramabana.core import forget_probes
_orig = dict(LIVE)
forget_probes(disk=True)
LIVE['openai'] = lambda: ['gpt-6-astra', 'gpt-6-nova', 'gpt-6-nova-2026-09-01', 'gpt-6-audio', 'gpt-4.1']
try:
    got = provider_models('openai')
    test_eq(got[:len(CATALOG['openai'])], list(CATALOG['openai']))
    test_eq(got[len(CATALOG['openai']):], ['gpt-6-nova'])
    test_eq(got.count('gpt-6-astra'), 1)
    assert 'gpt-4.1' in provider_models('openai', legacy=True)

    test_eq(provider_models('openai')[len(CATALOG['openai']):], ['gpt-6.1-nova', 'gpt-5.10', 'gpt-5.1'])

Through available_models

ramabana.core.available_models builds its hosted rows from provider_models. It includes a provider only when runtime_available and auth_status report that the provider can be used here. Each row has a value, label, provider and source. With a fake OpenAI key and listing, the OpenAI rows are the catalog followed by the one new model:

import ramabana.models as _m
from ramabana.core import available_models
_orig_live, _key = dict(_m.LIVE), os.environ.get('OPENAI_API_KEY')
forget_probes(disk=True)
_m.LIVE.update({'openai': lambda: ['gpt-6-astra', 'gpt-6-nova', 'gpt-6-nova-2026-09-01', 'gpt-6-audio'], 'anthropic': lambda: [], 'codex': lambda: []})
os.environ['OPENAI_API_KEY'] = 'sk-not-a-real-key'
try:
    rows = available_models()
    test_eq({tuple(sorted(set(r) - {'download'})) for r in rows}, {('label', 'local', 'model_id', 'name', 'provider', 'source', 'value', 'vendor')})
    openai = [r['label'] for r in rows if r['provider'] == 'openai']
    test_eq(openai, [*CATALOG['openai'], 'gpt-6-nova'])
    test_eq([r['value'] for r in rows if r['provider'] == 'openai'][0], 'openai/gpt-6-astra')
finally:
    _m.LIVE.clear(); _m.LIVE.update(_orig_live); forget_probes(disk=True)
    if _key is None: del os.environ['OPENAI_API_KEY']
    else: os.environ['OPENAI_API_KEY'] = _key

Names and vendors

A picker shows a name people know, not a model id. model_label(name) makes one: claude-opus-5-5 gives Claude Opus 5.5, gpt-4o-mini gives GPT-4o mini, and qwen3-4b gives Qwen 3 4B. A snapshot date and words such as it, mlx and 4bit are dropped. For a local model, repo is its download, which names it better than the short name. A name that you gave in config.toml stays as you wrote it.

vendor_of(name) names the company that hosts the model, or gives '' for a model on this machine.
