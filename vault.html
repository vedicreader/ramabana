vault

Memory that outlives the process: a vishalakshi vault behind the host,

Why a vault

LocalHost is the host the terminal runs on. It can read web pages and index the repository, but it keeps neither after the process ends. A page read in one session is gone in the next. The code index and the pages read live in separate stores that never meet.

A vishalakshi Vault is one SQLite file that holds documents of every kind: notes, web pages and research. VaultHost puts a vault behind the host. This adds three abilities.

  • Memory. LocalHost does not provide the memory group, and tools_for builds no memory tools for it. With a vault, the memory tools appear (memory_search, memory_read, remember, memory_forget) together with ask_memory. They answer from everything the vault has stored.
  • One search over everything. search_code asks three indexes at once: the vault for prose, kosha for identifiers and ripgrep for literal text. The three score results on unrelated scales. Vault.federate merges them by rank and ignores the scores.
  • Watches. A watch is a standing request that the vault stores. A scheduled watch is a job the vault runs on a schedule, such as re-reading a page every week or filing a reminder. A folder watch is a request to review changes under a folder, and Monitors carries it out. With a vault, the watch tools appear too (watch, list_watches, cancel_watch).

The host

VaultHost is a LocalHost with a vishalakshi vault. The constructor opens the vault in a background thread. Building the tool list never waits for an embedding model to load. The constructor declares the memory, ask and watch groups by taking them out of without, the set of groups a host switches off.

vault is a Vault, a path to one, or None for the shared default at ~/.vishalakshi/vault.db. shelf names a separate store inside the vault for this host’s writes. remember_reads files every page that read_url fetches. federate turns on the merged search. pii and pii_ner gate personal data and are covered below. mk_chat builds the chats that the vault uses to answer questions. graph_chat is the chat that builds the vault’s entity graph.

WorkspaceHost, in the same cell, is the host that mk_agent builds. It is both a VaultHost and a SpecHost. Both providers are off unless requested. vault=True (or a path, or a Vault) turns memory on. spec=True turns on the API tools from the spec notebook. When a provider is off, its groups stay switched off and calls fall through to LocalHost. WorkspaceHost adds two calls. add_worktree(repo, branch) makes a git worktree for a job and opens it as a root. run_cmd_bg starts a background command that logs to a file. It does not open a tmux pane.

The vault builds its entity graph with graph_chat only. When graph_chat is None, the host builds no graph unless $VISHALAKSHI_MODEL names a model. vishalakshi’s own default would load a local model. mk_chat answers the session’s questions and can be a hosted model. Memory

Memory search returns whole sections of stored documents, plus related sections found through the vault’s graph. Each section carries its age in seconds and whether it is stale. memory_tree lists the heading tree of each stored document, memory_read returns one section by its node id, and memory_forget deletes a document. These pass straight through to the vault.

remember stores a note. Notes are ordinary documents in the same store as everything else. A conclusion the agent reached comes back in the same search results as the evidence for it. The example stores two notes. A search in different words finds them.

host.remember('The weekly Coles order is milk, sourdough, eggs, baby spinach and olive oil.',
              title='weekly Coles order', tags=['groceries'])
host.remember('Ceres Fair Food delivers a mixed seasonal fruit box on Thursdays.',
              title='Ceres fruit box', tags=['groceries'])

r = host.memory_search('what do I need from the supermarket', limit=2)
[s['title'] for s in r['results']], {k: r['results'][0][k] for k in ('age', 'stale')}
test_eq(len(host.memory_tree()), 2)
test_eq(len(host.memory_tree('ceres')), 1)

node = r['results'][0]['node_id']
'olive oil' in host.memory_read(node)['text'] or 'fruit box' in host.memory_read(node)['text']

With a vault behind the host, tools_for offers the memory group. NullHost has no memory group.

from ramabana.tools import tools_for, NullHost

test_eq('memory_search' in have(NullHost()), False)
test_eq('memory_search' in have(host), True)

Gating what memory returns

Some of what a vault holds is personal data: names, emails and phone numbers. pii sets what happens when a section that the vault returns contains such data. off is the default and returns the section as stored. redact masks the personal parts. refuse withholds the section. pii_ner=True also catches titled names in addition to the pattern matches. vishalakshi does the gating. The host passes the setting into every vault read:

  • memory_search
  • memory_read
  • memory_tree
  • search
  • research

Either setting can be a function instead of a value. The host calls the function on every read. A settings panel can therefore change the setting during a session. A function that raises counts as off. The hidden cells check each mode against a note that contains an email address and a phone number.

Federated search

search, the host call behind search_code, asks the vault for prose, kosha for identifiers and ripgrep for literal text, and merges the three lists with litesearch.rrf_all through Vault.federate. If the vault fails to open, the host falls back to LocalHost.search.

In an empty temporary folder only the vault has anything to find. There is no kosha index, and there is no text file for ripgrep to match. search_note reports how many hits each index returned.

hits = host.search('seasonal fruit box', limit=5)
host.search_note

A prose hit’s symbol is its section’s node id. memory_read(hit.symbol) reads the whole section. A repository hit’s symbol is its module name, for use with symbols. One field serves the follow-up call for either kind of hit.

prose = [h for h in hits if h.symbol.count('#') == 1]
prose and host.memory_read(prose[0].symbol)['text'][:60]

federate=False turns the merging off and keeps LocalHost’s own search. A host also falls back to that search when its vault will not open.

plain = VaultHost(roots=[tmp], vault=tmp/'vault.db', index=False, web=False,
                  federate=False, warm=False)

Watches and reminders

Watches live in the vault, so they survive between sessions. poll runs the watches that are due. It does not rebuild the entity graph while a turn waits; when something ran, it starts connect, which rebuilds the graph in the background.

Each watch has an action and an interval. The simplest action is remind. When a reminder comes due, the vault files the reminder text back into itself as a note. A memory search finds the reminder together with everything else. The reminder does not wait in a notification queue that the harness does not own.

w = host.watch('Add the weekly groceries to the Coles trolley, and a Ceres fruit box.',
               action='remind', every='1w', note='weekly shop')
[(x['id'], x['action'], int(x['every'])) for x in host.watches()]

A new watch is first due at the moment it is created. A poll at any earlier time finds nothing to run.

test_eq(host.vault.poll(at=w['next_run'] - 1, connect=False)['ran'], 0)

A poll after that moment runs it, and a memory search then finds what it filed.

fired = host.vault.poll(at=w['next_run'] + 1, connect=False)
test_eq(fired['ran'], 1)
test_eq(fired['results'][0]['status'], 'ok')

hit = host.memory_search('what am I supposed to be doing about groceries', limit=3)
[s['title'] for s in hit['results']]

One failing watch must not stop the others. vishalakshi’s run_watch records a failure on the watch and returns it instead of raising. A poll over five due watches therefore runs all five. The vault runs each watch by calling its method named after the action. Replacing host.vault.url with a function that always fails makes every url watch fail. The example below puts one such watch next to a working reminder.

def _down(target, **kw): raise ConnectionError('name not resolved')
host.vault.url = _down

dead = host.watch('https://example.invalid/x', action='url', every='1d')
live = host.watch('check which day the Ceres box arrives', action='remind', every='1d')
out = host.vault.poll(at=max(dead['next_run'], live['next_run']) + 1, connect=False)
sorted(r['status'] for r in out['results'])

The failed watch is still there, rescheduled, with its last status recorded. A single failure does not delete a watch. The cleanup cancels both watches by hand.

host.unwatch(dead['id'])
host.unwatch(live['id'])
test_eq(len(host.watches()), 1)

The watch tools appear when the host provides the watch capability, as the memory tools do for the memory capability.

tools = have(host)
test_eq({'remember', 'watch', 'list_watches', 'cancel_watch'} <= tools, True)
test_eq(any(t.startswith('watch') for t in have(NullHost())), False)

watch is one tool for every kind of watch. Its kind is url for a page, remind for a reminder, search for a web query and folder for a path. The harness polls watches. The model does not. At the start of each turn, Agent.poll_watches calls host.poll() in a background thread, at most once every poll_every seconds, and reports what fired. The host returns failures instead of raising. A turn that starts by asking what is outstanding therefore does not end on an error.

from ramabana.tools import watch_tools

Using it

from ramabana import Agent
from ramabana.vault import VaultHost

host = VaultHost(roots=['~/code/myproject'])     # the shared ~/.vishalakshi/vault.db
agent = Agent(host, model='gpt-mini')

This agent has eight tools that a LocalHost agent does not have: the four memory tools, ask_memory and the three watch tools. Its search_code also answers from everything the vault has read. Agent needs no change. The tools appear because the host declares the groups they belong to.

Answering from material the model must not see

memory_search returns whole sections to the model. This suits research. It does not suit a bank statement. To answer from a section, the model that runs the turn must hold the section in its context. That model often runs on someone else’s servers.

ask, which the ask_memory tool calls, works in reverse. The vault answers and the caller receives only the answer. vishalakshi.pii detects personal information by pattern. It does not ask a model to read the sections first. When the retrieved sections hold personal information, the vault answers with a local model under a briefing that forbids repeating any personal detail. These cells are marked eval: false, and the test suite skips them.

In a real session, Agent.lend_model supplies mk_chat, and mk_chat honours the model it is asked for. The vault asks for its local model. It then checks that the returned chat runs on this machine. Without this check, a factory could send a statement to a hosted API. In the example, the factory returns a chat that claims a remote runtime. The vault refuses and sends nothing.

_h.mk_chat = _chat('remote', 'THIS MUST NEVER BE SENT')
_sent.clear()
r = _h.ask('what is on invoice 4471?')
test_eq(_sent, [])
test_eq(r.refused, True)
r.answer

A chat on a local runtime receives the question under a different briefing. It returns an answer that withholds the personal details.

_h.mk_chat = _chat('litert', 'One invoice, 240.00 GBP, due in September. Holding back the name, '
                             'email, phone and card. Tell me if you need a total, a date, or a yes/no.')
_sent.clear()
print(ask_memory('what is on invoice 4471?'))

That reply is half of a two-step exchange. The model that reads the reply decides what it needs and sends an instruction back. The instruction runs the local model again over the same sections. The model receives a useful answer, and the private material never leaves the machine.

_h.mk_chat = _chat('litert', 'Total 240.00 GBP, due 2026-09-01.')
_sent.clear()
out = ask_memory('what is on invoice 4471?', instruction='Give me the total and the due date only.')
test_eq('Give me the total and the due date only.' in _sent[0][1], True)
