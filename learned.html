learned

The review queue for <cfg>/learned: what Dhrona proposed waits on a branch until a person accepts or rejects it.

Dhrona’s nightly batch never changes the files Ramabana briefs from. It commits each candidate it keeps on its own pending/<id> branch of the learned folder’s git repository. The briefing and skill discovery read only the folder’s files, which are its HEAD, so a pending candidate has no effect until a person accepts it. --no-learned leaves out the folder whatever it holds.

pending lists what waits, diff shows one candidate’s change, accept moves it onto HEAD, and reject drops it. Each of diff, accept and reject returns a dict with ok and id, and error when ok is False, so a host such as Leela can show the result as it is. They take the lock a Dhrona batch holds, and refuse while a batch runs. accept also refuses a candidate that would take AGENTS.md past LEARNED_MAX, the 2,000 characters Dhrona allows one candidate, since accepted rounds add up.

compact asks Dhrona for a shorter AGENTS.md when accepted lessons crowd it. Dhrona’s editor model merges and shortens the paragraphs Dhrona proposed, keeps every paragraph a person wrote byte for byte, and commits the result as one more pending candidate, which diff, accept and reject act on like any other. compact(folder, id) also folds in pending candidate id, the case accept refuses for size: the refusal returns length and names /learned compact ID, and accepting that compaction accepts the candidate with it. compact returns {ok, id, before, after}, where before and after are the file’s length in characters, or {ok: False, error}. It needs the dhrona extra, and says so when Dhrona is missing. It runs one model turn, so it takes as long as that turn.

enabled

def enabled(
    cfg:str='~/.config/ramabana'
):

Whether learning is on: learning in this machine’s config.toml, which a value only <cfg>/settings.json holds moves into the first time it is read. On unless set off.

A candidate is accepted in a throwaway worktree first, so a conflict never leaves markers in the files a running session briefs from. HEAD moves only when the pick is clean. After it moves, restack moves every other candidate proposed on an older HEAD onto the new one where it picks cleanly, and accept returns those ids as moved. A candidate that no longer picks cleanly, for example one that edits a line a compaction rewrote, is listed as stale, and pending gives the reason in its stale field, so a host can show it beside the candidate. Ids sort by when Dhrona proposed them, which moving does not change. A candidate whose change HEAD already holds is accepted with commit None. The commit keeps Dhrona as its author, and its commit time is the moment of acceptance, which is where Dhrona’s 30-day expiry clock starts.

import os, json, time
def git(d, *a): return subprocess.run(['git', '-C', str(d), *a], check=True, capture_output=True, text=True).stdout.strip()
def propose(folder, files, id):
    "What Dhrona's `keep` does: a commit on `pending/<id>` off HEAD, the folder's files untouched."
    wt = Path(tempfile.mkdtemp())/'wt'
    git(folder, 'worktree', 'add', '-q', '-b', PENDING + id, str(wt), 'HEAD')
    for rel, text in files.items(): (wt/rel).parent.mkdir(parents=True, exist_ok=True); (wt/rel).write_text(text)
    git(wt, 'add', '-A'); git(wt, '-c', 'user.name=Dhrona', '-c', 'user.email=d@x', 'commit', '-qm', f'Lesson from a replay: {id}')
    git(folder, 'worktree', 'remove', '--force', str(wt))

learned_command is the text form a terminal shows. /learned in a session and ramabana-learned from a shell both use it: with no argument it lists what is pending, diff ID, accept ID and reject ID act on one, and compact proposes a shorter AGENTS.md.

Learning is one setting per machine, learning in config.toml (see setup), and it is on unless set off. set_enabled(cfg, False), /learned off in a session, or ramabana-learned off from a shell turn it off for every session on this machine, whatever its config folder. Off leaves the learned AGENTS.md and learned skills out of the briefing, drops the briefing’s rule to record lessons, keeps remember to plain notes, has Agent.lessons() return none, writes no start.json, and makes Dhrona’s nightly schedule return “learning is off” without touching the learned folder. Lessons already kept stay where they are, unread. The review queue still works, so a person can clear it. Agent(learned=False), the CLI’s --no-learned, turns learning off for one session only.

Ramabana 0.2.44 kept the switch in each config folder’s settings.json. When config.toml does not set learning, enabled(cfg) reads it from <cfg>/settings.json and writes it into config.toml, so a choice made there survives; the settings.json an embedding app shares is never written. A config.toml that is not valid TOML is never rewritten: set_enabled raises ValueError saying so, and /learned on returns that message:

with tempfile.TemporaryDirectory() as d:
    os.environ['RAMABANA_CONFIG'] = str(toml := Path(d)/'config.toml')
    try:
        assert enabled(d)
        test_eq(learned_command(learned_folder(d), 'off'), 'learning is off')
        test_eq((enabled(d), (Path(d)/SETTINGS).exists()), (False, False))
        assert '\nlearning = false\n' in toml.read_text()
        test_eq(set_enabled(d, True), True)
        toml.unlink(); (Path(d)/SETTINGS).write_text(json.dumps({'editor': {'tabSize': 2}, 'learning': 'off'}))
        test_eq(enabled(d), False)   # 0.2.44's setting moves to config.toml, and settings.json is left as it was
        assert 'learning = false' in toml.read_text() and json.loads((Path(d)/SETTINGS).read_text())['learning'] == 'off'
        toml.write_text('learning = [')
        assert 'not valid TOML' in learned_command(learned_folder(d), 'on') and toml.read_text() == 'learning = ['
    finally: os.environ.pop('RAMABANA_CONFIG')
