pane

What the main agent and each sub-agent are doing now, written to a file and drawn in a tmux split beside the chat.

While a turn runs, the chat shows the streaming answer and one line per tool call. It does not show how many tool calls the turn has made, how far the plan has got, what each sub-agent is doing, or which files have changed. The now pane shows these in a narrow column beside the chat. It shows the present: what runs now, what this turn has done, and the files the session has written.

The pane is a separate program, ramabana-pane, that runs in a tmux split. tmux is a terminal multiplexer. It divides one terminal window into panes, and each pane runs its own program. The session and the pane share information through a file. Up to five times a second the session writes a snapshot to now.json in the session’s run folder. The pane reads that file and draws it. This page covers the snapshot, the layout of a snapshot as rows of text, and the viewer that draws the rows and answers keys and clicks.

The snapshot

now_snapshot(agent) returns a dict that json.dumps can write. Its keys are:

  • at, the time of the snapshot, and busy, whether a turn is running.
  • root, the foreground turn: its tool-call count (steps), how long it has run, its state, the call it is waiting on (current), and its status, the last line the model wrote before calling a tool.
  • plan, the agent’s checklist, with each item’s text and status.
  • subs, one row per sub-agent. A sub-agent is a second agent that the turn starts to do part of the work. The list holds every delegation this turn started. It also holds every background delegation that is running or has finished since the turn began. A row has the sub-agent’s status, its tool-call count (steps), its last CALLS_KEPT calls with results cut to OUT_CHARS characters, and, once it has finished, its answer cut to ANSWER_CHARS characters. A finished sub-agent stays listed until the next turn starts.
  • files, every file written this session, the turns before this one included: path, lines added and removed against the file’s text at its first write, and the diff cut to DIFF_LINES lines. A file whose text is back to what it was, for example after /rewind, is not listed. A notebook is diffed as its cell sources.
  • notes, what the model wrote before each of this turn’s calls, in full and with a timestamp.
  • background, the work running behind the turn: background delegations, commands started with run_shell_bg, and folder watches. Each row has a kind, an id, a label, a state, the seconds it has been running (elapsed) and a detail text. A finished shell command and a folder watch have elapsed set to None.

The session writes a snapshot up to five times a second (PANE_EVERY in ramabana.cli, 0.2 seconds). A snapshot must be cheap to take when nothing has changed. The list of files is computed again only after a call finishes. The host is asked for the state of a running background shell command at most once every SHELL_EVERY seconds. It is never asked again once the command has ended.

Constant Value Limit
CALLS_KEPT 8 Latest calls kept for each sub-agent
OUT_CHARS 200 Characters kept of each call’s result
ANSWER_CHARS 500 Characters kept of a finished sub-agent’s answer
DIFF_LINES 80 Lines kept of each file’s diff
SHELL_EVERY 1.0 Seconds between state requests for a running background shell
SHELL_LINES 20 Output lines kept for a background shell

Each recorded call (an Act) names the run whose model made it. The steps value of a sub-agent is its tool-call count, the number of calls with its run id. The steps value of the main turn is its tool-call count, the number of calls whose parent_action_id does not name another call in the activity log. A sub-agent’s calls name the delegate call that started it. They never count toward the main turn’s tool-call count.

The sub-agent reads the same file before it answers. The activity log’s on_change hook takes a snapshot when the sub-agent’s read starts. At that moment the pane shows both agents working. The main turn has taken two steps, and the one sub-agent is running with one step:

The plan and the files the session wrote are part of the snapshot too, each file with its diff. Here the example sets a two-item plan and changes a.py by hand:

a.plan.set('ship', ['read a.py', 'fix it']); a.plan.update(a.plan.todos[0].id, status='active')

test_eq([(f['path'], f['added'], f['removed']) for f in snap['files']], [('a.py', 1, 1)])
print(snap['files'][0]['diff'])

Drawing it

board(snap, width) lays a snapshot out as rows for a pane width cells wide, one row per screen line. Each row is a (key, Text) pair, where Text is a rich styled string. Lines longer than the width are cut, not wrapped. Use board to get the rows, as the viewer does to find the row under a click. Use render to get something to print. It returns the same rows as one rich renderable.

From the top, the board shows:

  • A header with main, its step number, its clock and its status line. The header leaves out the call the main agent is waiting on, because the chat shows it. An idle agent’s header reads idle with the step count of the last turn.
  • The plan as a checklist, with the active item highlighted.
  • The sub-agents. The first row is main, with the text talk to the main agent. Then comes one row for each sub-agent: id, status line (or its question when it has none), clock, and a mark: ▶ running, ✓ completed, ✗ stopped or failed. An open row is marked ▾ in place of ▸. It adds the question, each recent call with its result, and the answer once there is one. An arrow marks the row that the terminal is aimed at.
  • The files the session wrote, each with its lines added and removed. An open row shows the diff, drawn by hl.diff_rich with the code coloured for the file’s language and the added and removed lines tinted.
  • The background work: kind, label, state and clock. A row opens to a shell command’s last SHELL_LINES lines of output, a watch’s pattern and last review, or a background sub-agent’s detail.
  • The notes, newest first, for reading back what the model said along the way. Each is a ▸ row with its time and first line, and opens to the whole note wrapped to the pane. The newest note starts open.

Empty sections are left out. A row that can open or be picked carries a key: ('main', 'main'), ('sub', id), ('file', path), ('bg', id) or ('note', at). The caller passes the keys of the open rows in open. A row stays open when the next snapshot arrives. A running clock adds the time since the snapshot was written. A long call does not look frozen between writes. The colours come from the snapshot: the terminal session writes its active palette as palette and its name as theme, so the board draws in the same colours as the main view, and a diff’s code in the matching HL_THEMES style. ramabana.cli imports this module, so this module cannot look the palette up in cli.THEMES, and the snapshot carries the colours themselves. PALETTE is the default github-dark palette, for a snapshot written without one.

In an open file the diff is drawn by hl.diff_rich in the pane’s palette. The code in each hunk is coloured by the file’s language, and added and removed lines get a tinted background. The cell checks that an added line carries more than two styles. That check shows the code is highlighted and not drawn in one colour:

The viewer

Viewer(path, tty) is the program that runs in the pane. It reads the snapshot at path and draws the board on tty. A tty is any object with read(timeout), write, size and restore, as teleprint’s RealTty has. PaneTty is RealTty with a read that returns None at the end of input, so the viewer can tell that its terminal has gone.

The viewer switches the terminal to the alternate screen and asks the terminal to report mouse clicks. The alternate screen is a separate screen for full-screen programs. The shell’s scrollback returns unchanged when the program exits. Each tick waits up to every seconds for input and acts on it. The controls are:

  • A click on a row picks it, and the mouse wheel scrolls. Picking the main row aims the terminal at the main agent: the viewer writes main to the talk_mark file beside the snapshot, and the CLI reads and removes the file, as /talk main would. Picking a sub-agent row leaves the terminal aimed where it was and opens that sub-agent’s transcript pane, which takes the lines typed to it. Picking a sub-agent, file, background or note row also opens or closes it.
  • j and k, or the arrow keys, move the cursor over the rows that open. Past the first or last such row they scroll, so a board taller than the pane can be read to its end.
  • Page up and page down scroll by a page, and g and G jump to the top and the bottom.
  • Enter picks the row under the cursor, as a click does. Space opens or closes that row and does not aim the terminal.
  • p on a background shell command opens a tmux pane below the viewer that follows the command’s log with less -R +F. q in that pane closes it.
  • q or ctrl+c quits.

The last line of the pane is always HINT. The main keys stay on screen however far the board scrolls. Every line is filled to the pane’s edge on the palette’s bg0, and the cursor row on its bg2.

Picking a running sub-agent that has a log opens a transcript pane. That pane is a tmux split left of the chat pane (the snapshot’s chat_pane) that follows the log in the board’s palette, as described under transcript panes below. The viewer keeps at most one transcript pane. Picking another sub-agent reuses it. Picking main closes it. The viewer closes it PANE_LINGER seconds (3.0) after the sub-agent ends or leaves the board, unless the snapshot’s close_done is false. The viewer never closes a pane that it did not open.

The viewer reads the snapshot again only when its file has changed. It lays out the board on every tick and writes only the lines that differ from what is on screen. A clock that moves once a second rewrites one line a second. A board that is not changing writes nothing. When the terminal changes size, the viewer clears it and draws everything again.

A failed frame does not stop the viewer. If drawing fails, the viewer keeps the last good snapshot and shows the error as a row until a good snapshot arrives. However the viewer exits, it restores the terminal’s normal screen and modes. When the user quits, the viewer leaves a file named by quit_mark beside the snapshot (now.closed). The terminal session checks for that file. It leaves a pane that the user closed closed, and it can tell such a pane from one that crashed. A hangup (tmux closing the pane), SIGTERM and the end of input count as quitting too.

The example drives a Viewer with a test terminal, Tty, that replays scripted input and keeps everything written to it. A click on the running sub-agent opens it and puts the cursor there. A tick with nothing new writes nothing. Then j moves the cursor down, space opens run_bbb, and q quits:

class Tty:
    "A terminal for tests: scripted input chunks, a size, and every write kept."
    def __init__(self, *input, size=(40, 30)): self.input, self.size, self.writes = list(input), size, []
    def read(self, timeout=0): return self.input.pop(0).encode() if self.input else b''
    def write(self, s): self.writes.append(s)
    def restore(self): pass
with tempfile.TemporaryDirectory() as d:
    (p := Path(d)/'now.json').write_text(json.dumps(busy))
    v = Viewer(p, Tty()); v.tick(now=now)
    y = next(i for i, (k, _) in enumerate(v.rows) if k == ('sub', 'run_aaa'))
    v.tty.input.append(f'\x1b[<0;3;{y + 1}M'); v.tick(now=now)
    test_eq((v.open, v.cursor), ({('sub', 'run_aaa')}, ('sub', 'run_aaa')))
    n = len(v.tty.writes); v.tick(now=now)
    test_eq(len(v.tty.writes), n)
    v.tty.input += ['j', ' ', 'q']
    for _ in range(3): v.tick(now=now)
    test_eq((v.cursor, v.open, v.done), (('sub', 'run_bbb'), {('sub', 'run_aaa'), ('sub', 'run_bbb')}, True))

Transcript panes

A transcript pane follows one run’s log, as tail -f would, but in the palette of the main view. Each log line is a time and an entry: > a call, < tool ok or < tool ERR its result, ~ a status line, user: a line the user sent, and question:, answer: or reply:. transcript_line colours one line by that role: the time gray, a call blue, a result green or red by its outcome, a status gray, the user’s words yellow. A line without a time, such as the second line of a long question, is plain fg1. transcript_ansi turns lines into terminal text a pane wide, each wrapped and filled to the edge with the palette’s bg0, as the viewer fills the board.

A Follower holds what one transcript pane has read and drawn. Each tick reads the whole lines written since the last one, keeping a partial line until its newline arrives, and returns the terminal text to write: the new lines, or '' when nothing changed. It reads the snapshot at path again only when that file changed, and keeps the last palette when the snapshot is missing or half written. A /theme in the main view therefore reaches the transcript within a tick: a new palette, or a new pane width, clears the pane and draws the last keep lines again. A log shorter than what was read has been rewritten, so the follower starts over. The last row of a transcript pane is its input line. While the snapshot lists a running sub-agent with this log, the row shows ▌ and the typed text, and the terminal’s cursor rests there, so only the pane tmux has focused shows a cursor. Enter sends the line to that sub-agent through the session’s control socket, whose path the snapshot carries as control. The control socket’s tell calls Agent.tell, which /talk uses too. The sub-agent’s transcript then shows the line as user:. A refusal, such as a sub-agent that has just finished, stays on the input line beside the text. A pane following any other log, or a sub-agent that has ended, takes no input and hides the cursor. follow(log, path) draws a Follower on the terminal above its input line, waiting up to every seconds for keys. setup.follow_cmd is the shell line that runs it, and both the viewer’s transcript pane and /watch use it.

main is the viewer’s command line: ramabana-pane PATH runs the viewer on the terminal it was started in. The terminal session starts it in a tmux split when you type /pane, and prints the command when there is no tmux, so you can run it in another terminal yourself. --every sets how long each tick waits for input. --log LOG follows that transcript in the snapshot’s palette, as a transcript pane does.
