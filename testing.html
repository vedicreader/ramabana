testing

In-memory hosts and scripted backends for tests and documentation.

Specs

A ModelSpec describes one model: its name, the runtime that serves it, the model id and the context window in tokens (ctx). The two specs here differ mainly in that window. SPEC has 1,000 tokens, small enough that compaction arithmetic can be checked by hand. Compaction is how the agent keeps a long conversation inside the window: it replaces older messages with a summary. SCRIPTED has 8,000 tokens. Compaction does not fire in the middle of a recorded demo.

SPEC, SCRIPTED.ctx

A host in memory

MemHost is a test host that keeps project files in a dict keyed by absolute path. The file and search tools read and write that dict. They do not touch the disk.

A host declares its abilities through the classes it inherits. Each capability class, such as CodeHost for code search or ShellHost for running commands, names one capability group. tools_for(host) builds the tools of every group the host declares. Every host has the file group from Host. MemHost inherits from NullHost, CodeHost and ShellHost. It declares the file group and the groups of those two capability classes. It declares no other group. The live Python session group is one of the groups it lacks, and host.can('session') is False. A test uses this class to check that a missing group removes its tools.

MemHost sets writes = True. NullHost sets it to False, and file_tools then withholds the editing tools.

commands scripts the shell. It maps a command string to (exit_code, output). A command not in the dict exits with code 0 and no output. Every command that runs is appended to host.cmds as (command, cwd, timeout). The cell below builds a host with two files.

search returns every file whose text contains the query as a substring, up to limit files. It returns Hit objects, the type a real code index returns. Each hit reports line 1 and the first line of the file, not the line that matched. search_note is 'memory'.

host.search('return a'), host.search_note

write stores text in the dict and returns the path. text_at reads it back and returns an empty string for a file that does not exist. Agent.changes() reads files through text_at. A test can check which files a turn edited against this host.

host.write('/proj/c.py', 'def c(): pass\n')
host.text_at('/proj/c.py'), host.text_at('/proj/never.py')

run_python appends the code to host.ran and returns 'ok'. It starts no kernel. A test can check what the agent tried to run. A test must call the method directly, because MemHost does not declare the session group and tools_for builds no run_python tool for it. The cell after the example checks this. host.provides lists the groups the host declares.

host.run_python('df2 = df.dropna()'), host.ran
test_eq(host.can('session'), False)
test_eq(names(tools_for(host)) & {'run_python', 'list_vars', 'inspect_python'}, set())
sorted(host.provides)

A host with everything

LocalHost is the host the terminal session runs on. It has real folders on disk, a real shell and a real Python kernel. Some of its groups need something a test does not have. Memory and watches need a vault, the web tools need the network, and its inspect_python has only the isolated scope. A test cannot exercise those tools on a LocalHost.

FullHost is a LocalHost that fills each gap with a small implementation over in-process state. Its web is a dict of pages you pass in. Its memory stores the pages it reads and searches them. Its terminal is a transcript you pass in. Nothing reaches the network. It works in a new temporary folder unless you pass root. A test or a docs page can write files there freely. Three groups stay off because they need a model, an API specification or a vault: ask, api and watch.

Underneath it is a real LocalHost. The sandbox that keeps every path inside the open folders, the file tools and the Python namespace are the production code. The next cells view a file through the real view_file tool, show a path outside the folder being refused, and run Python in the live namespace.

view_file, replace_text, create_file, add_root = file_tools(host)

test_fail(lambda: host.check('/etc/passwd'))
host.run_python('total = threshold_calls = 0\ntotal'), host.list_vars().splitlines()

The web is the dict of pages passed in. web_search matches the query against each page’s url and text. read_url returns a page. Unless remember=False is passed, read_url also stores the page in memory. The memory tools below search those stored pages.

web_search, read_url = web_tools(host)
print(web_search('nbdev'))
print(read_url('https://nbdev.fast.ai/api/export.html')[:80])

Memory is where the agent keeps pages and notes beyond the current conversation. A memory search returns sections of a stored document, each with a breadcrumb naming the document and heading it came from, rather than loose snippets. FullHost makes those sections by splitting a page at its headings, and memory_tree lists the headings of each stored document.

memory_search, memory_read, remember, memory_forget = memory_tools(host)
host.memory_search('duplicates')
test_eq(len(host.remembered), 1)
host.memory_tree()[0]['headings']

memory_forget deletes a stored document and its sections. The same search then finds nothing.

doc_id = next(iter(host.remembered))
memory_forget(doc_id), host.memory_search('duplicates')

research searches the web, reads every page that matches and returns them as one digest, with a source line under each page. It belongs to an opt-in tool group: tools_for(host) leaves it out and tools_for(host, optin='research') includes it. This cell builds the tool directly with shalya.research_tools.

from shalya import research_tools
research, = research_tools(host)
print(research('export')[:220])

inspect_python lets the agent look at the user’s live Python namespace. It has two scopes. The isolated scope runs the code against a copy of the namespace. The overlay scope runs it against the real namespace and sees every object as it is. FullHost runs the overlay scope, then restores every name that existed before the run.

Restoring bindings undoes an assignment such as kept = None. It does not undo a change made inside an existing object. The cell below defines kept, a list in the live namespace. The next cell appends to it from the isolated scope.

host.run_python('kept = [1, 2, 3]')
host.inspect_python('kept.append(99)\nlen(kept)', scope='overlay'), host.run_python('len(kept)')

The isolated scope copies the namespace dict, not the objects in it. A new name defined there disappears. kept is the same list in both scopes. The append changes the real list. The output shows the length of the real list after the append.

host.inspect_python('kept.append(4)\nlen(kept)', scope='isolated'), host.run_python('len(kept)')

read_terminal reads the terminal beside the agent. On FullHost it returns the transcript passed as terminal. note is how a host leaves a message for the agent, such as a report that compaction ran. FullHost also appends every note to host.notes. A test can check that list.

read_terminal = {t.__name__: t for t in session_tools(host)}['read_terminal']
print(read_terminal())
host.note('compacted 12 messages')
host.notes

A backend with no model

FakeBackend replies from a list of strings, in order, and replies (done) once the list runs out. It subclasses the real Backend. These parts are production code:

  • the lock that serialises calls
  • the usage accounting
  • the list of problems shown to the user
  • the history replacement that compaction uses

Only the replies are made up. sent holds every message sent, and spawned holds every sub-agent backend that spawn made. A one-shot call is a single call for a short job such as a summary. On FakeBackend it returns ONESHOT: followed by the first 40 characters of the prompt.

''.join(FakeBackend(replies=['streamed one word at a time']).stream('go'))

use is a Usage record of tokens in and out. A live backend reports the same type. Two Usage records add with +. FakeBackend counts 10 input tokens and 5 output tokens for each message sent, as a running total.

be.use, be.use + be.use

fake_agent builds a real Agent and routes all of its jobs to one FakeBackend. A job is one kind of model call the agent makes: the turn itself, a summary, a classification, a sub-agent. Normally each job can go to a different model. With every job routed to the fake, no call reaches a real model. The routing applies only when you pass neither model nor routing. The agent leaves out the user’s ~/.agents/skills and has no beat, so a test briefs and prompts the same on every machine. Pass global_skills=True to read the skills.

The host is a MemHost with one file unless you pass host. Other keyword arguments go to Agent. fake_agent returns (agent, backend). A test scripts the replies and then reads what the backend received. Use fake_agent when a test needs a whole turn. Use FakeBackend alone when a test needs only a backend.

A real model, recorded

The doubles above run the agent with no model. A docs page that shows what a real model does needs another tool. A multi-gigabyte model is too slow in CI, and a pasted transcript is never checked. recorded stores real answers and replays them.

Inside with recorded(): every chat the agent opens is urai’s CachedChat. A CachedChat stores the model’s answer the first time. The stored answer is keyed by the model, the briefing, the tools and the conversation so far. Later runs replay the stored answer and start no model. Every runtime counts as available inside the block. A page can replay Claude’s answers on a machine without Claude Code.

Answers are stored in CHATS, the chatcache folder next to the ramabana package folder, unless you pass path. record=False only replays. record=True sends a miss to the real model and stores the answer. With record=None the URAI_RECORD_CHAT environment variable decides.

The key leaves out two kinds of chat option. The first kind is a value that keyable rejects, such as a callable, whose repr holds an address that changes between runs. The second kind is the UNKEYED options, timeout_hint and api_key. Recorder passes both kinds to the live chat only.

The example uses an empty cache with record=False. The one-shot call returns an empty string, and the backend’s problems say that no recording was found.

VaultHost is the host with durable memory from the vault notebook. It rebuilds its memory graph in a background thread with a chat called graph_chat. no_model returns a stand-in chat that answers {} to every prompt. Pass it as graph_chat or as mk_chat, and the thread starts no model. nbdev’s test runner runs several notebooks in each worker process. Two notebooks that load a model onto the GPU at once can crash the worker.

Compaction, end to end

Compaction replaces the older part of a conversation with a summary followed by the most recent messages. The agent compacts on its own when the tokens used reach the threshold, and agent.compact() compacts on demand. The threshold is max(1, ctx - min(reserve, max(1, ctx // 4))), which is 750 tokens for the 1,000-token window of SPEC. After twelve more questions the fake_agent history is below 750 tokens, and agent.compactor.due(backend) returns False. Compaction always keeps the 18 most recent messages, so the loop asks enough questions to leave older ones to summarise. The cell after the loop compacts anyway. The fake’s one-shot answer is the summary.

for i in range(12): agent.ask(f'question {i} about the exporter')
len(backend.hist), agent.compactor.due(backend)
summary = agent.compact()
agent.compactor.note

The history now begins with the summary. The text after it tells the model what happened: its conversation was rewritten, but the Python kernel was not, so the user’s variables are still there.

print(backend.hist[0]['content'][:200])
test_eq(backend.hist[0]['content'].startswith('Previous conversation summary:'), True)
test_eq(agent.compactor.count, 1)
agent.compactor.last[:60]

A backend that mutters

Local model engines sometimes fail without raising. The engine prints its error to its own output stream and returns an empty string. The caller sees an empty reply with no reason. Ramabana’s local backend keeps what the engine printed and adds it to the backend’s problems. MutteringBackend reproduces the failure, and a test can check that handling. GEMMA is a real error line from the LiteRT engine, kept as the engine printed it.

mute.send('again')
test_eq(len(mute.problems), 1)
mute.spec.ctx

A backend that performs

ScriptedBackend plays a list of Steps. A step can call a tool, say some text, or both, and can pause first. The text streams out one word at a time, token_delay seconds apart. The delay is for screenshots. At zero the turn finishes before the screen repaints, and every capture shows a finished answer instead of one in progress.

A tool step looks the tool up by name in the backend’s tool list, which refresh sets, and calls it. The agent’s own tools are in that list. The activity feed, the approval gate and the file snapshots then run as they do in production. A step that names a tool missing from the list skips the call, and the step’s text still plays. Use FakeBackend to test logic. Use ScriptedBackend for demos where the tool calls have to happen.

A real model with every tool

The doubles above check control flow. This last section checks the assembled product: a FullHost, an Agent over it on a made-up remote model, and every tool the host supports handed to the model’s conversation.

Everything runs inside recorded(). It starts no model and makes no network call. Two cells would talk to the model. Both carry #| eval: false, and the test suite skips them. Run by hand, they check that the model compiled every tool schema and that it can answer.

from contextlib import ExitStack

replay = ExitStack()
replay.enter_context(recorded())

# `remote`: `resolve` refuses a runtime that is not installed
register_model('release-model', 'openai/release-model', 'remote', 32_768)
real_host = FullHost(
    files={'pkg/sizes.py': 'RESERVE = 16_384\n\ndef threshold(ctx):\n    return ctx - RESERVE\n'},
    pages={'https://example.test/nbdev': '# nbdev export\n\nOne module belongs to one notebook.'},
    terminal='$ pytest -q\n69 passed')
real_agent = Agent(real_host, model='release-model', extensions=False)
for job in ('classify', 'summary', 'completion', 'subagent'):
    real_agent.routing.set('release-model', job)
real_agent.start() is not None, real_agent.note
(False,
 'turn job: release-model needs OPENAI_API_KEY; set it in the environment. `/login` adds a provider in a session, `ramabana setup` from a shell')

test_eq(len(real_backend.chat.toolspecs), len(real_agent.tools))

(real_backend.spec.model_id, len(real_backend.chat.toolspecs))
